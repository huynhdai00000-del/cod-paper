# Is the scalar-500 clamp a model defect or a property of the loss?

Generated by `audit_port/scripts/30_scalar500_clamp.py`. Ground truth only — no model is involved, so this holds for every cell trained with the shared physics loss.

## What the clamp is

`ode_physics_loss_shared` truncates the prediction with a **scalar** `clamp(0, 500)` before forming the residual. `ode_physics_loss`, which `train_v34` uses, instead applies the per-state vector `[200, 500, 200, 1000, 3000, 8000]`. So COD and Ablation A (`loop: train_v34`) and the six C-11 baselines (`loop: train_physics`) are **not** trained under the same clamp.

## Reading

**The ceiling truncates physically correct states**: `c_CO`, `c_CO2` exceed 500 in ground truth, well inside their own per-state ceilings. A model predicting those values *correctly* is clamped anyway, and its residual is then formed at a state it did not predict.

So `clamp_frac_state_scalar_500` firing throughout training is **a property of the shared loss on this distribution, not of the architecture**. It should be expected in every cell using `loop: train_physics` — FNO, MIONet and S-DeepONet, all six — and to be absent in COD and Ablation A, which use `train_v34` and its per-state vector. That is exactly the pattern observed, and it is not evidence about FNO.

**Consequence for C-11.** The method and the baselines are trained under different clamps, and the baselines' is the tighter one on the gas states. That is a systematic disadvantage to every baseline in the matrix, and it is not an architectural difference. It has to be resolved before the remaining cells run, or the comparison measures the loss rather than the architecture.
